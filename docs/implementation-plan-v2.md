# Vocabulary Enrichment — Implementation Plan v2 (Revised)

## What Failed in v1

The original plan was: "generate 7,800 JLPT words in batches using AI." No field-level rules, no validation, no test batch, delegated to a sub-agent. Result: 7,296 garbage entries (dictionary definitions, meta sentences, Japanese in non-JP fields).

## v2 Principles

1. **Every field has an explicit source and constraint.** Nothing is "just generated."
2. **Test batch of 30 first.** Human approval before scaling.
3. **No sub-agents.** I generate each batch directly with explicit field-by-field instructions.
4. **Validate before merging.** Check every entry against constraints.

## Per-Field Specification

For a Japanese word X at JLPT level L:

### `id`
- **Source**: Auto-incremented from max existing ID
- **Constraint**: Must be unique integer

### `ja`
- **Source**: From JLPT word list
- **Constraint**: The Japanese word as-is from the master list

### `ja_furi` (furigana reading)
- **Source**: JMdict kana reading for kanji form X
- **Fallback**: If X is hiragana-only, `ja_furi` = X
- **Constraint**: Must contain hiragana. Must NOT equal X if X contains kanji.
- **Validation**: `has_kana(ja_furi)` AND `ja_furi != ja` when `has_kanji(ja)`

### `ja_roma` (romaji)
- **Source**: Hepburn romanization of `ja_furi`
- **Constraint**: Must contain only ASCII letters. No kanji, no kana, no punctuation.
- **Validation**: `all(c.isascii() and not c.isspace() or c == ' ' for c in ja_roma)`

### `ja_ex` (Japanese example sentence)
- **Source**: Written at correct JLPT level
- **Level rules**:
  - N3: Plain form, 10-18 chars, natural daily conversation
  - N2: Mixed politeness, 15-25 chars, abstract topics
  - N1: Formal/academic, 20-30 chars, specialized vocabulary
- **Constraint**: Must USE the word X naturally. Must NEVER mention "JLPT", "N1", "N2", "N3", "レベル", "語彙", "表現", "用語", "重要".
- **Validation**: `'N1' not in ja_ex and 'N2' not in ja_ex and 'N3' not in ja_ex and 'レベル' not in ja_ex and ja in ja_ex`

### `en` (English translation)
- **Source**: JMdict English gloss for X. Take the FIRST gloss only.
- **Constraint**: Must be 1-3 English words. NOT a dictionary definition with semicolons or commas. If JMdict has "peaceful; tranquil; calm", take ONLY "peaceful".
- **Validation**: `len(en.split(';')) == 1 and len(en.split(',')) <= 2 and len(en) < 40`

### `en_ex` (English example sentence)
- **Source**: Translation of `ja_ex` into natural English
- **Constraint**: Must translate the SAME meaning as `ja_ex`. Must not mention "JLPT", "N1", etc.
- **Validation**: `en_ex != ja_ex and 'N1' not in en_ex and 'term' not in en_ex.lower()`

### `zh` (Chinese translation)
- **Source**: Kanji → Simplified Chinese mapping. Use character-level conversion where possible. For words not mappable, use the English word as reference to produce single Chinese word/phrase.
- **Constraint**: Single Chinese word/phrase in simplified characters. No Japanese kana. No dictionary definitions.
- **Validation**: `not has_kana(zh) and len(zh) < 15 and ';' not in zh`

### `zh_pin` (pinyin)
- **Source**: `pypinyin` library applied to `zh`
- **Constraint**: Tone marks, space-separated. No semicolons.
- **Validation**: Generated by `pypinyin` — always valid

### `zh_ex` (Chinese example sentence)
- **Source**: Translation of `ja_ex` into natural simplified Chinese
- **Constraint**: Must translate the same meaning. Must USE the Chinese word `zh`. No mention of "JLPT", "N1".
- **Validation**: `zh in zh_ex`

### `ko` (Korean translation)
- **Source**: Hanja → Hangul mapping via character-level conversion. For non-mappable words, use English reference.
- **Constraint**: Single Korean word/phrase in hangul. No Japanese kana or kanji.
- **Validation**: `not has_kana(ko) and not has_kanji(ko) and len(ko) < 15`

### `ko_roma` (Korean romanization)
- **Source**: Revised Romanization of `ko`
- **Constraint**: ASCII only. No hangul, no CJK.
- **Validation**: `all(ord(c) < 128 for c in ko_roma)`

### `ko_ex` (Korean example sentence)
- **Source**: Translation of `ja_ex` into natural Korean
- **Constraint**: Same meaning, natural Korean. Must use `ko`.
- **Validation**: `ko in ko_ex`

### `es`, `pt`, `it`, `fr`, `de` (European translations)
- **Source**: Translate from English word `en` to single target-language word
- **Constraint**: ONE word (or short natural phrase). NOT a dictionary definition. NOT identical to English.
- **Validation**: `len(val) < 30 and val != en and ';' not in val and val != 'null' and val != 'None'`

### `ru` (Russian translation)
- **Source**: Translate from English word `en` to single Russian word
- **Constraint**: Cyrillic. Single word or short phrase.
- **Validation**: `any(0x0400 <= ord(c) <= 0x04FF for c in ru)`

### `ru_tr` (Russian transliteration)
- **Source**: Latin transliteration of `ru`
- **Constraint**: ASCII only.
- **Validation**: `all(ord(c) < 128 for c in ru_tr)`

### European `_ex` fields (es_ex, pt_ex, it_ex, fr_ex, de_ex, ru_ex)
- **Source**: Translation of `ja_ex` into target language
- **Constraint**: Same meaning. Natural sentence. Must use the translation word.
- **Validation**: Translation word appears in the sentence

### `level`
- **Source**: Constant per tier ("N3", "N2", "N1")
- **Constraint**: Must match the JLPT level of the word

### `tags`
- **Source**: Derived from level
- **Constraint**: N3 → ["N3", "B1", "TOPIK3"]; N2 → ["N2", "B2", "TOPIK4"]; N1 → ["N1", "C1", "TOPIK5"]

## Batch Validation Checklist

Before merging each batch of 30, verify:
1. `[ ]` No entry has `ja_furi == ja` when `ja` contains kanji
2. `[ ]` No entry has `ja_roma` containing kanji or kana
3. `[ ]` No entry has `en` containing semicolons (dictionary definition)
4. `[ ]` No entry has `ja_ex` mentioning "N1", "N2", "N3", "JLPT", "レベル"
5. `[ ]` No entry has `ko` or `zh` containing Japanese kana
6. `[ ]` No entry has identical values across `es`/`pt`/`it`/`fr`/`de`/`ru`
7. `[ ]` No entry has `null` or `None` as a string value
8. `[ ]` Every `_ex` field contains the translated word somewhere in the sentence
9. `[ ]` All 28 fields present for every entry
